# Word 转 Markdown 工具的核对笔记

这份项目内资料记录《Word 转 Markdown》一文依据的转换逻辑。它概述一个独立的 Python 工具，未把本机目录作为公开来源。

## 阅读顺序

工具遍历 Word 文档 body 的直接子节点，根据 `w:p` 与 `w:tbl` 分别构造段落和表格对象：

```python
def blocks(doc):
    for child in doc.element.body.iterchildren():
        if child.tag == qn("w:p"):
            yield Paragraph(child, doc)
        elif child.tag == qn("w:tbl"):
            yield Table(child, doc)
```

这样能保留顶层段落与表格的相对顺序。嵌套布局仍需另行处理。

## 代码、标题与表格

工具首先检查代码样式，再计算等宽字体字符比例；比例达到 `0.85` 时，按代码处理。连续代码段会被同一个 Markdown 围栏包裹。

表格转换把首行作为表头，补充分隔行。单元格内多行文字被合并，竖线被替换为斜杠。这些是便于输出的取舍，可能改变代码或业务值。

当前标题识别逻辑先判断样式名是否包含中文“标题”，随后才尝试匹配英文 `heading`。对于只使用英文 `Heading 1` 的文档，需要单独验证。部分中文级别映射也是针对既有模板的约定，不能直接视为通用规则。

## 质检范围

配套的质检脚本统计 Markdown 文件长度、标题数、代码围栏数和表格数，并检查围栏数量是否为偶数。它可用于初筛，不能证明围栏位置、代码缩进或复杂表格完全正确。

工具会跳过某些图片样式段落；没有完整的图片资源导出链路，因此目前更适合文本导向的内容转换。
